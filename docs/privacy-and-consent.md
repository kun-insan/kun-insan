# Privacy & consent

## Principles
- **The user's data belongs to the user.** Private by default.
- Two parts: a **private** part for the user only, and one clearly defined **shared** part with the project, only with explicit consent.
- Full visibility: see, edit, delete everything.
- **No personal data ever in this repository.** Synthetic examples only.

## Separate consents
1. Using data to improve the product
2. Publishing anything (case studies, quotes): only after the user sees and approves the final text
3. Psychological-state data (Feel AI)
4. Recording other people (meetings): everyone recorded must agree

## Trust
- Verified users and real scores from real interactions.
- Clear agreements: users must be able to trust it 100%, and the project must be legally protected. The intention is only to help humanity.

## Built on standards, not reinvented
- Legal frameworks: GDPR (EU), Egypt Personal Data Protection Law 151/2020, Saudi PDPL, and local law where users live.
- Security: proven cloud services for identity, key management, sensitive-data discovery, audit logs and model guardrails, plus encryption at rest and in transit.

## Never stored
Government ID numbers, card or bank account numbers, passwords or tokens, and anything the user asks to forget.

## Reporting a privacy issue
Open a private security advisory on GitHub or contact the maintainers listed on the organization profile. Please don't open a public issue for vulnerabilities.
